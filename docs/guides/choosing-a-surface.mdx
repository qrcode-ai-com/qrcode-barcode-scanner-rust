One Rust core, five published runtime entry points and separate mobile bindings, the [same JSON report](/api/report). Pick by where
your code runs:

| Your context | Surface | Install |
|---|---|---|
| Rust app / service | [`qrcode-barcode-scanner`](/api/rust) | `cargo add qrcode-barcode-scanner@=0.12.2` |
| Shell scripts, CI gates | [CLI `qrscan`](/api/cli) | `cargo install qrcode-barcode-scanner-cli --version 0.12.2 --locked` |
| Node server (Nuxt/Next/worker) | [`@qrcode-ai-com/qrcode-barcode-scanner`](/api/node) | `npm install --save-exact @qrcode-ai-com/qrcode-barcode-scanner@0.12.2` |
| Browser | [`…-wasm`](/api/wasm) | `npm install --save-exact @qrcode-ai-com/qrcode-barcode-scanner-wasm@0.12.2` |
| Python | [`qrcode-barcode-scanner`](/api/python) | `python -m pip install qrcode-barcode-scanner==0.12.2` |
| Native Android | [Kotlin](/api/mobile) | from source |
| Native iOS / macOS | [Swift `QRCodeBarcodeScanner`](/api/mobile) | `.package(url: "https://github.com/qrcode-ai-com/qrcode-barcode-scanner-swift.git", from: "0.12.0")` |
| Cross-platform app | [Flutter](/api/flutter) | `flutter pub add qr_barcode_scanner:0.12.0`; signed precompiled native library, or Rust built at app-build time |

<Note>
The five runtime packages are public in 0.12.2 under these names. Node selects
one matching native platform dependency automatically; the browser package
contains one portable WASM plus its included camera and overlay modules.
The [migration guide](/guides/migrate-to-qrcode-barcode-scanner) keeps old
packages separate. Flutter is also public on pub.dev; its
[dated native consumer evidence](/api/flutter#native-consumer-evidence) records
Android and iOS builds with and without Rust, not yet a qualified scan on an
emulator, simulator or device. The Swift package 0.12.0 is public by repository
URL and listed on the [Swift Package Index](https://swiftpackageindex.com/qrcode-ai-com/qrcode-barcode-scanner-swift); a macOS consumer scanned
with it, not yet an iOS simulator or device. Kotlin retains its source-build
limits; a binding is not a mobile application.
</Note>

## What each surface needs to *install*

- **Rust / Cargo CLI** — a Rust toolchain. The release also provides prebuilt
  CLI archives, which need no Rust compiler at installation.
- **Node / WASM** — the published native dependency or portable `.wasm`.
  No Rust toolchain is needed to consume these packages.
- **Python** — a matching published `abi3` wheel needs no Rust toolchain;
  a source build does. See the [wheel platforms and tested interpreter](/api/python).
- **Kotlin/Android** — source build; no qualified JitPack release is claimed.
  Building needs Rust and the Android NDK.
- **Swift/iOS** — SwiftPM fetches the prebuilt `.xcframework` that the
  package's `Package.swift` pins by its checksum; no Rust toolchain is needed.
  Building the local source package in `bindings/swift` needs Rust and the
  platform SDK.
- **Flutter** — install `qr_barcode_scanner` from pub.dev. At application build
  time, cargokit links a signed precompiled native library, by default on a
  machine without rustup or when the app opts in. Otherwise it compiles the
  bundled core, which needs Rust 1.88 or newer and the platform toolchain,
  including Android NDK r28 or newer.
  The [Flutter guide](/api/flutter) records the public consumer limits.

Container and agent adapters reuse these runtimes but keep separate publication
and consumer evidence. The published MCP adapter, ClawHub skill and OpenClaw
bundle are documented in the [agent integration guide](/guides/agents), including
their installed-consumer scope. They use existing scanner runtimes and do not
add a sixth scanner SDK. Prepared integrations still require their own publication.

## Picking a profile

Every surface takes a `profile`: `full` (full ladder + scannability score — the
generator quality gate), `fast` (reduced, for upload tools), `frame` (per-frame
camera decode, no scoring). Default is `full` (`frame` for the `scanFrame` entry
points). Bound the worst case with a budget (see each surface's API page).

Whatever you pick, the result is the **same versioned [`ScanReport`](/api/report)** —
machine-validated against the [normative spec](https://github.com/qrcode-ai-com/qrcode-barcode-scanner-rust/tree/main/spec)
in CI, so you can prototype on one surface and ship on another.
