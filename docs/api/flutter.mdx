Use `qr_barcode_scanner` to scan encoded images or application-supplied RGBA
camera frames in a Flutter app. The package returns a typed `ScanReport` from
the shared native Rust engine. Your app supplies camera access, permissions,
preview and the action taken after decoding; this package is a scanner binding.

You can try the [QR code scanner](https://qrcode-ai.com/en-US/qr-code-scanner)
and [barcode scanner](https://qrcode-ai.com/en-US/barcode-scanner) in a browser
before adding native scanning to an app. The [QR code scanner Flutter guide](https://qrcode-ai.com/en-US/qr-code-scanner/sdk/flutter)
and [barcode scanner Flutter guide](https://qrcode-ai.com/en-US/barcode-scanner/sdk/flutter)
connect the two development journeys. Prepare test images with the
[QR code generator](https://qrcode-ai.com/en-US/qr-code-generator) or
[barcode generator](https://qrcode-ai.com/en-US/barcode-generator), keep the
original payload, and compare that exact value with each decoded result.
If a product guide is unavailable, use the API and build instructions here.

## Install the published package

Public Flutter package [`qr_barcode_scanner` 0.12.0](https://pub.dev/packages/qr_barcode_scanner/versions/0.12.0)
is published under verified publisher [`qrcode-ai.com`](https://pub.dev/publishers/qrcode-ai.com/packages).
In an existing Flutter project:

```bash
flutter pub add qr_barcode_scanner:0.12.0
```

The public archive declares Dart `>=3.9.2 <4.0.0`, Flutter `>=3.35.3` and
`flutter_rust_bridge` exactly `2.13.0`. Up to 0.11.0 the package declares Dart
`>=3.3.0 <4.0.0`, Flutter `>=3.19.0` and `flutter_rust_bridge` `2.12.0`.
These declarations are not evidence of installation on every SDK version.
Android and iOS are the plugin's declared platforms. For an upcoming source
candidate, follow the
[separate packaging instructions](https://github.com/qrcode-ai-com/qrcode-barcode-scanner-rust/blob/main/bindings/flutter/README.md#packaging-from-a-candidate-checkout);
they do not replace or republish the archive on pub.dev.

## Precompiled or built native library

The package ships `rust/cargokit.yaml`. When your app builds, cargokit, which
drives the Rust part of the build, first looks for a native library
precompiled from the exact package sources, in the engine's GitHub release
[`precompiled_bb4bac3bc00d4d8d9fd8b35826e8e649`](https://github.com/qrcode-ai-com/qrcode-barcode-scanner-rust/releases/tag/precompiled_bb4bac3bc00d4d8d9fd8b35826e8e649).
It downloads the library and its Ed25519 signature, and links the library
only if the signature verifies against the public key in `rust/cargokit.yaml`.
The release covers Android (`armeabi-v7a`, `arm64-v8a`, `x86`, `x86_64`) and
iOS (devices, Apple silicon simulators and Intel simulators). Its libraries
are built with the release profile, and debug app builds use them too.

- On a machine without rustup, cargokit uses the precompiled library by
  default.
- With rustup installed, cargokit compiles the core unless the app opts in
  with a `cargokit_options.yaml` next to its `pubspec.yaml`:

  ```yaml
  use_precompiled_binaries: true
  ```

<Warning>
When cargokit compiles the Rust core at **your app's build time** (rustup is
installed and the app does not opt in, or no library with a valid signature is
available), the building machine needs the **Rust toolchain (≥1.88)** and, for
Android, the **NDK (r28+)**, which aligns the native library for 16 KB memory
pages. A one-time `rustup` install; no Rust knowledge required.
</Warning>

Up to 0.11.0 the package ships no `rust/cargokit.yaml`, and every app build
compiles the core.

## API

```dart
import 'package:qr_barcode_scanner/qr_barcode_scanner.dart';

await QrcodeAiScanner.init();                       // once, before any scan

// encoded image (PNG/JPEG/WebP/GIF) → typed ScanReport
final report = await QrcodeAiScanner.scan(pngBytes); // profile: 'full' (default)
// transparent PNGs flatten engine-side ('auto') — read report.alpha for the
// resolved background + placement envelope (the facade exposes no override yet)

// raw RGBA camera frame (width*height*4 bytes), no scoring
final frame = await QrcodeAiScanner.scanFrame(rgba, w, h); // profile: 'frame'

// a wall-clock budget in milliseconds (0 = unbounded)
final slow = await QrcodeAiScanner.scan(pngBytes, budgetMs: 10000);
```

Published 0.12.0 does not expose `capabilities()` (spec/01 § Capabilities);
its native library carries the core's default engines.

Scans run on flutter_rust_bridge's Rust worker pool, so `await` never blocks the
UI isolate. Profiles: `'full'` · `'fast'` · `'frame'`, each under its default
wall-clock budget (4000 · 800 · 80 ms), which starts once the image is decoded
and normalized. A
report the budget cut says so: `report.trace.budgetExhausted == true`; a null
`score` beside a detection then means "not judged", never 0. A null
`budgetExhausted` is an older report: unknown, never final.

Unlike the Kotlin/Swift bindings (which return a JSON string), Flutter ships a
**typed** [`ScanReport`](/api/report) — sealed `Payload`/`Hint`, `Score` with the
ISO 15415 / UEC grade cards. Unknown enum values and payload kinds decode to
`unknown` / catch-all variants, never a throw (additively forward-compatible) —
except `Charset` and `Fnc1Position`, whose newer wire values decode to
`unrecognized`. `Charset.unrecognized` is still a complete reading:
`Charset.unknown` is the wire's own lossy value, so test
`d.content.charset.isLossy` (then use `d.content.raw`, the payload's bytes).
`d.content.eci` and `d.content.fnc1` are null when none was observed or the
symbology does not report it — not proof that the symbol declares none;
compare contents by symbology, `raw`, `fnc1` and `eci`, never by text.

```dart
if (report.detections.isEmpty) {
  // 'no QR found' — a result, not an error
} else {
  final d = report.detections.first;
  print('${d.content.text}  •  ${d.payload.kind}  •  ${report.score?.grade.name}');
}
```

## Scan budget

`scan` and `scanFrame` take an optional `budgetMs` argument, with the
semantics of `budget_ms` in the other bindings
([spec/02 § Budget semantics](https://github.com/qrcode-ai-com/qrcode-barcode-scanner-rust/blob/main/spec/02-profiles.md#budget-semantics)):

| `budgetMs` | Budget |
|---|---|
| `null` (omitted) | the profile's default |
| `0` | unbounded: the scan runs its whole ladder, the reproducible mode (not a zero-millisecond budget) |
| 1 to 4294967295 | that many milliseconds |
| above 4294967295 | refused before the image is read: the call throws a `String` ending with `[QRS-006]` |
| negative | refused before the native call: `RangeError`, without a code |

A call without `budgetMs` keeps its meaning: each profile keeps its default
budget. Up to 0.11.0 the package has no `budgetMs`.

The budget stops the scan from starting a stage or an attempt once its
deadline has passed. It does not stop one that is running. So a `frame` scan
can take longer than 80 ms and still be final: its last stage started in time,
and `budgetExhausted` is `false`.

The Flutter package does not take the `formats` option yet: it looks for
every symbology.

Simulators and emulators run Flutter in debug mode. When cargokit compiles the
core there, it uses the package's dev profile, which the package optimizes
(opt-level 3, no debug assertions, no LTO); up to 0.11.0 that profile is not
optimized. A signed precompiled library is built with the release profile and
serves debug builds too. The
[package README](https://github.com/qrcode-ai-com/qrcode-barcode-scanner-rust/blob/main/bindings/flutter/README.md#debug-builds-and-scan-time)
gives the dated CI timings of the mixed QR/Code 128 fixture with the dev
profile. They are CI observations of source builds, not device performance.

## Errors + license

A scan fault throws a `String` ending with the `[QRS-xxx]` wire code
([catalog](/api/errors)); an unknown profile name throws without a code, and
a negative `budgetMs` throws a `RangeError`.
The report shape is the [one contract](/api/report).
